# Чат-бот сообщества ВКонтакте

Каркас на **Lumen 10**, **MySQL 8** и Docker. Приложение принимает события сообщества по Callback API, хранит карточку сообщества, участников и журнал активности. Ответы пользователям на этом этапе не включены: сначала нужно убедиться, что ВКонтакте достучалось до локального сервера.

PHP на компьютере ставить не нужно. Он работает внутри контейнера.

## Чем это отличается от Telegram

В Telegram бот — отдельный аккаунт: BotFather выдаёт токен за пару минут, и этот бот может сидеть в разных чатах.

Во ВКонтакте официальный бот — это **само сообщество**. Отдельного «бота-пользователя», которого добавляют в чужие группы, у платформы нет. Личный аккаунт, который сам читает чужие беседы, ВКонтакте блокирует, поэтому здесь так делать не будем.

Одно сообщество = одна строка в `vk_groups` = один ключ доступа. Если ботов несколько, в это же приложение регистрируется каждое сообщество отдельно. Робот понимает, кому отвечать, по полю `group_id` во входящем событии.

Для своего сообщества **не нужны** юрлицо, договор и модерация приложения. Отдельное приложение на [dev.vk.com](https://dev.vk.com) для базового бота тоже не нужно: хватает ключа из настроек сообщества. Нужен обычный аккаунт ВКонтакте, в котором вы администратор сообщества. Иногда ВКонтакте просит подтвердить телефон — это единственная проверка.

По времени это дольше трёх кликов BotFather, обычно **10–15 минут** в интерфейсе, если сообщество уже есть. Сложность не в допусках, а в том, что настройки разложены по разным вкладкам и сервер должен быть доступен по HTTPS.

## Что получить на стороне ВКонтакте

Нужны четыре вещи. Первые три выдаёт ВКонтакте, четвёртая — секрет, который придумываете вы.

| Что | Где взять | Куда положить |
| --- | --- | --- |
| Ключ доступа сообщества | Управление → Дополнительно → Работа с API → Ключи доступа | `access_token` в `POST /api/groups` |
| Числовой id сообщества | Адрес вида `club123456` или `public123456` | `vk_group_id` |
| Строка подтверждения | Callback API, блок сервера, строка для подтверждения | `VK_CONFIRMATION_CODE` в `.env` |
| Секретный ключ, до 50 символов | Придумываете сами, одну и ту же строку | Поле «Секретный ключ» в ВКонтакте и `secret_key` в API |

Ключ сообщества показывается один раз. Если он потеряется, старый удаляют и создают новый.

При создании ключа отметьте права:

- **Сообщения сообщества** — читать входящие и отвечать;
- **Управление сообществом** — забрать список участников и карточку группы.

Строка подтверждения в интерфейсе сообщества и строка из метода `groups.getCallbackConfirmationCode` — **разные**. Для кнопки «Подтвердить» на сайте нужна строка из интерфейса. Если ВКонтакте покажет новую строку, впишите её в `VK_CONFIRMATION_CODE` в файле `.env` и сохраните файл: следующее подтверждение уже ответит новым значением, контейнер перезапускать не нужно.

Клиентский SSL-сертификат в Callback API — необязательная защита. Для локальных тестов он не нужен: туннель уже отдаёт HTTPS.

### Порядок в интерфейсе

1. Создайте сообщество или откройте своё: [vk.com](https://vk.com) → Сообщества → Создать. Это бесплатно.
2. Управление → Сообщения → **Сообщения сообщества: включены**. Ниже включите возможности ботов. Если бот должен отвечать не только подписчикам, разрешите писать всем.
3. Управление → Дополнительно → Работа с API → создайте ключ с правами выше. В части кабинетов этот раздел называется «Настройки → Работа с API».
4. Запустите локальный проект и туннель (ниже) и скопируйте HTTPS-адрес.
5. Зарегистрируйте сообщество в нашем API (`POST /api/groups`) **до** нажатия «Подтвердить». Иначе рукопожатие придёт в пустую базу.
6. Работа с API → Callback API → добавить сервер:
   - адрес: `https://<адрес-туннеля>/api/vk/callback`
   - секретный ключ: та же строка, что `secret_key`
   - версия API: **5.199**, или самая новая `5.1xx` из списка
7. Нажмите «Подтвердить». ВКонтакте пришлёт `confirmation`, сервер должен ответить строкой подтверждения.
8. В типах событий включите:
   - входящее сообщение (`message_new`)
   - исходящее сообщение (`message_reply`)
   - вступление в сообщество (`group_join`)
   - выход из сообщества (`group_leave`)
   - разрешение и запрет сообщений (`message_allow`, `message_deny`)
9. Заберите текущих участников: `POST /api/groups/{id}/sync`.

Вкладка «Запросы» в Callback API показывает, что именно ВКонтакте отправило и что ответил сервер. Если там `forbidden`, секрет в кабинете и в базе не совпал. Если `unknown group`, сообщество ещё не зарегистрировано или `vk_group_id` другой.

## Запуск

Из папки `chatbot`:

```powershell
docker compose up --build
```

Первый запуск скачивает образы и зависимости PHP, это несколько минут. Приложение: [http://localhost:8080](http://localhost:8080). Проверка базы: [http://localhost:8080/health](http://localhost:8080/health).

MySQL снаружи: `127.0.0.1:3306`, база `chatbot`, пользователь `chatbot`, пароль `chatbot`. Порт меняется через `FORWARD_DB_PORT` в `.env`.

При первом старте, если `ADMIN_TOKEN` ещё заглушка, контейнер запишет случайный токен в `.env` и напечатает его в лог. Это пароль **нашего** API, не ВКонтакте. Им закрыты методы, которые принимают ключ сообщества. Callback для ВКонтакте остаётся открытым и проверяет секрет сообщества.

После правки `.env` контейнеры нужно пересоздать, не просто перезапустить:

```powershell
docker compose up -d
```

Тесты:

```powershell
docker compose exec app vendor/bin/phpunit
```

Синхронизация участников из консоли, аргумент — id ВКонтакте или id строки в нашей базе:

```powershell
docker compose exec app php artisan vk:sync 123456
```

## Туннель в интернет

ВКонтакте не умеет слать события на `localhost`. Постоянный адрес — поддомен `melnikovbot.ru` и именованный туннель Cloudflare. Сертификат и ключ туннеля лежат в томе `chatbot_cloudflared`, адрес задан в `cloudflared/config.yml`. Запуск:

```powershell
docker compose --profile named up -d cloudflared-named
```

Адрес для ВКонтакте: `https://bot1.melnikovbot.ru/api/vk/callback`. Он не меняется при перезапуске контейнера.

## API приложения

Заголовок для всех методов, кроме callback: `X-Admin-Token: <ADMIN_TOKEN>`.

Зарегистрировать сообщество:

```powershell
curl.exe -X POST http://localhost:8080/api/groups ^
  -H "X-Admin-Token: ВАШ_ТОКЕН" ^
  -H "Content-Type: application/json" ^
  -H "Accept: application/json" ^
  -d "{\"access_token\":\"КЛЮЧ_СООБЩЕСТВА\",\"confirmation_code\":\"СТРОКА_ИЗ_КАБИНЕТА\",\"secret_key\":\"секрет-до-50-символов\",\"vk_group_id\":123456}"
```

Ответ содержит `id` — это id строки у нас. Его используют остальные адреса. `vk_id` — id во ВКонтакте. Ключ сообщества в ответах не возвращается.

| Метод | Что делает |
| --- | --- |
| `GET /api/groups` | Список сообществ |
| `GET /api/groups/{id}` | Карточка и сырой ответ `groups.getById` |
| `POST /api/groups/{id}/sync` | Обновить карточку и список участников |
| `GET /api/groups/{id}/members` | Участники |
| `GET /api/groups/{id}/activity` | Журнал событий |
| `GET /api/groups/{id}/stats` | Счётчики событий и число известных участников |
| `POST /api/vk/callback` | Адрес для ВКонтакте, без админского токена |

Повторный `POST /api/groups` с тем же сообществом обновляет ключ, секрет и строку подтверждения.

Хозяин бота задаётся в `.env` числом `VK_OWNER_ID`. Это id пользователя ВКонтакте, не id сообщества. На его сообщения бот отвечает репликой ВКонтакте: соглашается с утверждениями и отвечает на вопросы. Если другой участник отмечает сообщество в сообщении, бот отвечает ему репликой ВКонтакте. Чужое сообщение без отметки получает реакцию, если в нём есть «Виктор», «Витя» или то же имя латиницей. Если обращения без почёта, бот отвечает замечанием на это сообщение. Если `VK_OWNER_ID` пустой, бот не отвечает никому.

Текст ответа пишет локальная модель в контейнере `ollama`. Характер задаётся в `LLM_SYSTEM_PROMPT`: в переписке, которую видит модель, ваши реплики подписаны «Хозяин». При `LLM_ENABLED=true` и `VK_AUTO_REPLY=true` бот отвечает на ваши сообщения и на чужие, где отмечено сообщество. Если модель недоступна, уходит запасная фраза `VK_AUTO_REPLY_TEXT`. Модель по умолчанию — `qwen3:8b`. Другое имя задаётся в `OLLAMA_MODEL`, после смены выполните `docker compose --profile pull run --rm --no-deps ollama-pull`. На сообщение в личке или беседе бот также ставит реакцию `VK_REACTION_ID` (1 — первая реакция в списке ВКонтакте, обычно сердечко). На фото, видео, аудио и запись, которые принадлежат хозяину и пришли в этом сообщении, вызывается `likes.add`. Чужой контент, просто пересланный в чат, не лайкается.

## Что лежит в базе

- `vk_groups` — сообщества, в которых работает бот: название, адрес, описание, число участников, фото, сырой ответ API, ключ, секрет и строка подтверждения.
- `vk_users` — люди, которых бот увидел: участники после синхронизации и те, кто написал или вступил.
- `vk_group_members` — связь человека с сообществом, роль руководителя, признак «сейчас состоит», можно ли писать ему от имени сообщества.
- `activity_events` — журнал: входящие и исходящие сообщения, вступления, выходы. Повтор одного и того же события ВКонтакте не дублируется.

Сообщение само по себе не делает человека участником: написать сообществу может и неподписчик. Участники появляются из синхронизации и из событий вступления и выхода.

Lumen 10 — последняя ветка этого микрофреймворка, её достаточно для API. Позже те же адреса можно перенести на Laravel, если понадобится кабинет и очереди.
